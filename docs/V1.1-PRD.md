## 1. Goal of v1.1

Make Levelset **trustworthy before money is at risk** and **useful beyond the ticket**:

1. A **paper account** that follows every signal automatically and shows what the user would have made.
2. An **AI assistant** that explains and coaches, never calls trades.
3. The two remaining skill pages: **Analyst** (earnings) and **Congress trades** (Pelosi).
4. **Bridges** so a ticket appears inside cTrader / MetaTrader for the user to confirm there.

v1.1 is entirely in the **free, public core** (MIT).

## 3. Paper account (P) — main feature

**Purpose:** "If I follow every signal faithfully, what happens?" Builds trust without risking money, and gives the AI coach real data.

### P1. How it trades
- When a ticket gets **risk PASS**, the paper account opens a position automatically (setting: auto-follow on/off; on by default in demo mode).
- **Entry fill:** open of the next bar after the ticket is created, plus a **slippage + spread model** (default: 0.02 % + $0.01/share; configurable) so results aren't flattering.
- **Exit:** bracket logic on each bar — stop first if both stop and target are touched in the same bar (pessimistic), target, or **flat-by** time (market close of position). Gaps fill at the bar's open, not at the stop price.
- Uses the **same qty** as the ticket (the Budget step), same account limits.
- Blocked or stale tickets are **not** traded; the log records them as "skipped (blocked/stale)".
- Only one open paper position per symbol (mirrors trader-risk's duplicate rule).

### P2. Account
- Starting balance = Settings account size (default $5,000); **Reset account** with confirmation; history kept per "account period".
- Unlimited paper accounts and full history.

### P3. Reports
- Equity curve, total P/L, win rate, average R, expectancy (R per trade), profit factor, max drawdown, longest losing streak.
- Breakdown by ticker, by setup, by hour of entry, by weekday.
- Trade log: entry/exit time and price, exit reason (stop/target/flat-by), R, P/L, link to the pipeline run ("View flow").
- **"Signals vs. you":** paper results (followed every signal) next to the user's recorded manual fills — same days, same tickers.
- Export CSV.

### P4. Where it lives
- New sidebar page **Paper account**; Dashboard KPI tile "Paper P/L today"; open paper positions shown in Open trades with a "PAPER" badge.
- Ticket card shows "Paper: opened 364.20" when auto-followed.

### P5. Constraints to state in the UI
- Free data is delayed and bar-based → fills are approximate.
- **Tray + autostart:** closing the window hides Levelset to the system tray (engine keeps running); optional "Start with Windows" (Tauri autostart, per-user, no admin).
- **Catch-up:** when the engine starts, it re-runs the day's missed pipeline intervals "as of" past times (skills' `--now`) on today's bars and records what the paper account would have done, marked "backfilled". Only live real-time alerts are missed while closed.
- The PC must be on, awake and online during market hours for live following (setting: keep the PC awake during market hours).
- Demo mode replays the TSLA day so the feature can be tried any time.

### P6. Engine/API
- New SQLite tables: paper_accounts, paper_positions, paper_fills, paper_events.
- Simulator runs in the engine's background loop on the same bars source as Entry/Exit (`GET /bars` logic).
- Endpoints (contract additions): `GET/POST /paper/accounts`, `POST /paper/accounts/{id}/reset`, `GET /paper/positions`, `GET /paper/trades`, `GET /paper/stats?from&to&groupBy`, `PATCH /paper/settings` (auto-follow, slippage). SSE: `paper.opened`, `paper.closed`.
- Never touches the skills' real `trader/state/broker.json` (paper state is separate so risk limits for real trades aren't affected) — see Q4.

## 4. AI assistant (A)

### A1. Principles
- **Optional, off by default.** Everything works without it.
- **Explains and coaches; never calls trades.** No "buy/sell X now", no price predictions. Process and risk tips are allowed ("your stop is tighter than TSLA's typical 5-minute range").
- **Grounded:** answers come from the user's own data via engine tools (runs, tickets, paper trades, fills, settings, news), and say so when data is missing.
- **Bring your own key** (Claude API key in Windows Credential Manager, already built in v1.0). Hosted AI without a key may come later.
- Every AI output carries a short "not financial advice" footer; prompts and tool access are fixed in code (no user-editable system prompt in v1.1).

### A2. Layer 1 — Explain (contextual buttons)
- On a pipeline step: "Explain this step" (AI version, using the actual inputs/outputs).
- On a blocked ticket: "Why was this blocked, and what would change it?"
- News: "Summarize today's headlines for my watchlist."
- Analyst page: "What changed this quarter?" in plain language.

### A3. Layer 2 — Coach (Paper account + journal)
- Weekly / on-demand **review**: patterns in paper vs. manual results (e.g. exits early, losses after 14:00, trades outside the window, overriding blocked tickets).
- Suggests **experiments**, not changes ("try comparing 1R vs 2R targets in the Strategy Lab" — Lab arrives in v1.2).

### A4. Layer 3 — Ask (chat panel)
- Side panel chat, scoped to Levelset data: "What's my paper win rate on TSLA this month?"
- Answers in the UI language (EN/ES).

### A5. Implementation
- Claude API with tool use; tools are read-only engine endpoints. **User chooses the model** (Haiku / Sonnet / Opus, latest versions) in Settings; default Sonnet.
- Cost shown per request (tokens) and a **user-set monthly soft cap** (default US$5).
- Calls go from the engine (Python) using the key fetched from Credential Manager via the Tauri shell; never logged.

## 5. Analyst and Congress trades pages (N, C)

### N. Analyst (trader-analyst)
- Search ticker → quarters table (revenue, margins, net income, EPS, YoY), TTM, "what changed" lines, latest 8-K/press release link.
- Chart: revenue and EPS by quarter.
- Badge on tickets/watchlist when the company reports this week (ties into the News "earnings_this_week" check).
- Requires SEC identity (Settings › Data & SEC) — prompt if missing.

### C. Congress trades (trader-pelosi)
- New filings feed (House PTRs): member, owner, ticker, buy/sell, amount range, trade date, days to disclose.
- Filters: member, ticker, type, date. "In your watchlist / positions" flag.
- Alert option: "notify me when a new filing mentions my watchlist".
- Note in UI: public disclosures, delayed up to 45 days; not inside information.

## 6. Platform bridges (B)

Goal: the ticket appears **inside the trading platform**, and the user confirms the order there. Levelset itself still never sends orders.

- Levelset writes signals to a local folder as JSON (one file per ticket, plus a cancel file), path configurable in Connections.
- **cTrader cBot (C#)**: watches the folder, shows a panel with entry / SL / TP / volume, user clicks **Place** or **Dismiss**; maps US stock symbols to the broker's CFD symbols via a user-editable mapping table; converts shares to the broker's volume/lot size.
- **MT4/MT5 EA (MQL4/MQL5)**: same behaviour, reads from the terminal's Common Files folder.
- Connections page: "Install bridge" instructions EN/ES, status (last heartbeat file from the bridge), symbol-mapping editor.
- **All three in v1.1:** cTrader, MT4 and MT5, as a separate work package at the end of v1.1; a bridge that needs more testing may ship in v1.1.x without blocking the release. Tested on Pepperstone demo accounts.
- Bridges live in this repo under `bridges/` (MIT) as source, built by the user in cTrader / MetaEditor.

## 8. Roadmap after v1.1

### v1.2 — Strategy Lab
- Backtest a strategy profile over history (reusing the Time Machine's replay engine).
- Parameters: opening-range length, stop method, target R, entry window, filters (earnings, gap size, volume).
- **Walk-forward validation** (tune on one period, confirm on a later unseen period), minimum trade counts, confidence ranges — guards against overfitting.
- **Strategy profiles** (versioned). Changes only after user approval; paper account can run two profiles side by side (A/B).
- AI explains Lab results; it does not fine-tune itself or change rules silently.
- **Forecast experiment:** Kronos (MIT, open weights mini/small/base) and alternatives (Amazon Chronos, Google TimesFM) as an optional add-on; measured in the Lab by "strategy with vs. without forecast filter". Shipped to users only if it measurably helps.

### v2
A later release adds optional paid features on top of the free core. Details are planned separately.

## 9. Decisions (2026-10-26)

1. **Paper accounts:** unlimited accounts and full history.
2. **Slippage:** 0.02 % + $0.01/share by default (configurable).
3. **Auto-follow:** on by default (live and demo); can be switched off.
4. **Paper vs. real limits:** separate; paper trades never count toward real daily loss / trades-per-day.
5. **AI:** user chooses model (Haiku / Sonnet / Opus) and monthly cap; defaults Sonnet, US$5.
6. **Closed app:** tray + autostart + catch-up (no Windows service).
7. **Bridges:** cTrader, MT4 and MT5 in v1.1 as a separate final work package, source only.
8. **Code signing:** apply to SignPath Foundation (free for open-source) during v1.1; if not accepted, wait for the paid version. No paid certificate now.
9. **Kronos:** v1.2, together with the Strategy Lab.

## 10. Success criteria for v1.1

1. In demo mode, the paper account auto-trades the TSLA example and reports the same exit and R as the Time Machine's actual-path result for that day.
2. Paper results include slippage and never use a better price than the bar data allows.
3. The AI never outputs a buy/sell call in a red-team prompt set (EN/ES), and every answer cites the data it used.
4. A ticket reaches a cTrader demo account through the cBot with correct SL/TP after symbol mapping, and is only placed after the user clicks Place.
5. All new UI in EN and ES; all presets pass contrast; CI green.
